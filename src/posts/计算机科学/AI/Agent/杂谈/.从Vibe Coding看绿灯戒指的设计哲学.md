# 从Vibe Coding看<span style="font-weight: bold; color: green;">绿灯戒指</span>的设计哲学

> [!TIP]
>
> - 哈尔·乔丹：“我心里想得出什么，就能创造出什么——只要我集中意志。”
> - 约翰·斯图尔特：“<span style="font-weight: bold; color: green;">戒指</span>成就不了灯侠，是灯侠成就了<span style="font-weight: bold; color: green;">戒指</span>。”
> - 凯尔·雷纳：“<span style="font-weight: bold; color: green;">戒指</span>只受想象力的限制。”

如果你看过[<span style="font-weight: bold; color: green;">《绿灯军团》</span>](https://movie.douban.com/subject/36225837/)，你一定记得那个画面：一枚小小的<span style="font-weight: bold; color: green;">绿灯戒指</span>套上手指，绿光一闪，心里想到什么，手上就出现什么。最近我也在看这部美剧，主角们说的话让我醍醐灌顶——<span style="font-weight: bold; color: green;">绿灯戒指</span>被称为宇宙中最强大的武器之一，但它的力量从来不来自<span style="font-weight: bold; color: green;">戒指</span>本身，而来自佩戴者的**意志**。

<!-- more -->

`Vibe Coding` 实际上也是和绿灯戒指类似的东西：`AI` 成就不了程序员，是程序员成就 `AI`。

> [!TIP]
>
> `Vibe Coding` 这个词的发明者 `Andrej Karpathy` 说，这是一种“完全交出代码控制权”的玩法——不读 `diff`，报错就原样丢回模型，直到程序“差不多能用”。他同时把适用范围说得很窄——一次性的周末项目。

任何一个人打开 `Claude Code` 的那一刻，都会面临两个和灯侠一模一样的问题：<span style="font-weight: bold; color: green;">你有多清楚自己要什么，以及你愿不愿意为生成出来的代码负责</span>。

这两个问题，在漫画里叫“意志”和“恐惧”，在编程里叫“需求定义”和“代码审查”。

## 一、<span style="font-weight: bold; color: green;">戒指</span>不给你意志，它只放大意志

> [!TIP]
>
> 哈尔·乔丹那句台词是整个绿灯设定的地基：“<span style="font-weight: bold; color: green;">我心里想得出什么，就能创造出什么——只要我集中意志。</span>”
>

注意后半句。**“集中意志”不是蛮力，是清晰的意图。** 他能用戒指造出精密仪器，不是因为力气大，而是因为脑子里先有那台仪器的完整图像。漫画里有一段：盖伊·加德纳被人拦腰斩断，所有人都以为他死了——他躺在地上，用戒指一寸一寸把自己重新拼了回来。那一刻戒指没有变得更强，变得更强的是他不想死的意志。

放到 `Vibe Coding` 里，这句话翻译过来就是：**AI 只会放大你的能力，不会凭空替你制造能力。**

同样一句“帮我做个抽奖页面”，A 拿到的是全网抽奖页的平均水平，B 拿到的是一个产品——因为 B 说的是“每天限抽三次，抽中先播三秒动画，动画播完才能看到结果”。提示词差三句话，产出差一个档次。文末引用的那篇文章说得更狠：你有一技之长，AI 让你快十倍；你一无所有，AI 只放大你的混乱。

------

## 二、<span style="font-weight: bold; color: green;">绿灯侠</span>无法想象出自己不知道的东西

> [!TIP]
>
> 凯尔·雷纳说“<span style="font-weight: bold; color: green;">戒指只受想象力的限制</span>”。这话还有个被忽略的前半句：<span style="font-weight: bold; color: green;">想象力本身有边界，边界就是知识</span>。
>

约翰·斯图尔特是建筑师出身，他的造物永远有承重墙。漫画里有个细节值得玩味：他先研究了盾构机的图纸，才用灯戒把它造了出来。图纸在前，造物在后——灯戒能瞬间造出万物，唯独造不出他脑子里没有的东西。

漫画里的灯侠们也不是生来就会造一切。戒指连着军团世代积累的图纸和知识库，他们同样要学，学完才会造。这和 `AI` 一模一样：`Copilot` 的强大来自 `GitHub` 上无数开源代码的喂养，它学过的模式比你多，但你没装进脑子里的，它也不会替你装上。

所以 `Vibe Coding` 的坑，只有懂行的人才看得见。

比如 AI 很爱写 `if (status == "XXX")`：把一个来历不明的字符串直接焊死在判断条件里，业内叫**魔法数**。老手一眼就知道这是病——判断条件应当来自常量或枚举，而不是凭空蹦出来的字面量。可没系统学过计算机的人不会觉得这行有问题：能跑啊。坑就埋在“能跑”这两个字里。

更别说层层嵌套的 `try catch`、AI 特有的过度优化、上下文一长就出现的“记忆错乱”……没亲手写过代码的人，连该在哪儿警觉都不知道。

所以：灯侠造不出他不知道的东西，Vibe Coder 也审不出他看不懂的代码。**AI 只能在你的视线之内工作——你看不见的坑，它不会替你看。** 这样的代码不会自己消失，只会一年比一年难维护。

------

## 三、三种用<span style="font-weight: bold; color: green;">戒指</span>的方式，也是三种 Vibe Coder 的姿态

一枚绿灯戒指落到不同人手里，有三种用法，每一种都对应着 `Vibe Coding` 里的一种姿态。

### 1. 把意志交给<span style="font-weight: bold; color: green;">戒指</span>（全盘接受 AI）

这是 `Vibe Coding` 最原始的样子：不读 `diff`，报错原样丢回模型，改到“差不多能跑”就收工。这是把戒指当成了主人——**戒指造什么，你就收下什么，自己的判断一次都没出场。**

代价是累积的：生成得越快，你没看懂的代码攒得越快。魔法数、嵌套的 `try catch`、谁也解释不了的“能跑”逻辑——用不了多久，你就会变成仓库里最陌生的那个人：代码全是 AI 写的，没有一行你能说出它为什么存在。

它并非一无是处。`Karpathy` 自己就把适用范围圈得很小：一次性脚本、周末玩具。错了就删，代价趋近于零。

怕的是把“周末玩具”的心态带进生产环境——真出了事，你连报错都解释不了。

### 2. 拒绝戴上<span style="font-weight: bold; color: green;">戒指</span>（坚持全部手写）

另一个极端：所有代码必须亲手敲，AI 一律不碰。这是把戒指锁进抽屉，坚信不戴戒指才算真本事——**固执己见，拒绝让步。**

开源世界真有人这么干，理由还不软：`Zig`、`OpenJDK` 直接拒绝 AI 生成的代码进仓库；`Linux` 内核要求 `Signed-off-by` 必须是真人，AI 的参与只能记进 `Assisted-by`。这些项目反对的不是技术，而是“没有人对代码负责”的提交。

但对个人来说，一味拒绝同样要付代价：手敲脚手架、搬接口、翻文档，时间全耗在 AI 十秒就能干完的活上。拒绝升级工作方式的开发者，输的不是手速，是时间。

它最适合的场景是学习。从零敲过代码的人，才看得出 AI 的代码哪儿不对——就像从没训练过的灯侠，连个光球都捏不稳。**跳过训练直接戴戒指，等于把大楼盖在别人的图纸上，而你看不懂那张图纸。**

### 3. 人戴<span style="font-weight: bold; color: green;">戒指</span>，人机共创

第三种，是绿灯军团的方式：**戒指戴在自己手上，把 AI 的输出和自己的判断都留下来，融成新的东西。**

灯侠戴戒指，但造什么由灯侠决定；AI 生成代码，但哪一行能留下由你决定。`Simon Willison` 给过一个判断标准：代码是模型写的没关系，只要它经过你的审查和测试，并且你讲得清每一行在干什么，你就依然在做软件开发。

拿魔法数走一遍流程：

```java
// AI 生成的第一版：魔法数直接上场
if (status == "XXX") {
    // 没人知道 XXX 是什么，以后更没人知道
}

// 你提出约束：判断只依赖常量或枚举，重写，并补上测试
// AI 交回的第二版：
if (status == OrderStatus.CANCELLED) {
    // 语义清晰，可维护，可测试
}

// 最终版：你审查 diff、跑完测试、能解释每一行，才放进仓库
```

这不是“AI 写、你粘贴”，而是**AI 出速度，你出方向**：生成交给模型，审查、解释和拍板留在自己手里。

适合它的是所有要交付给别人的代码：登录、权限、支付、密钥、数据迁移——解释权必须留在人手里。

而每完成一次这样的人机合并，你对系统的掌控就厚一分。因为你证明了：**你能让 AI 跑得飞快，同时依然知道它为什么这么跑。**

想判断此刻该用哪种姿态，只问一句：**明天它要是坏了，你说得清它为什么坏、修得好它吗？** 说不清，今天就不算开发完。

------

## 四、恐惧：灯戒唯一的弱点

绿灯戒指的力量来自意志，它唯一的弱点，是恐惧。

漫画里，灯侠一旦被恐惧攥住，光构就会颤抖、变暗，最后散成一地碎光。所以军团选人只有一个标准：**不是看谁最有力量，而是看谁能克服巨大的恐惧。** 戒指从不奖励毫无畏惧的人，它奖励的是怕得要命、仍然举起手的人。

`Vibe Coding` 里的恐惧长这样：

- 你讲不清自己的业务逻辑，于是指望 AI 替你讲清；
- 出了BUG，你感到恐惧，于是你指望 AI 替你找出。

可 AI 只会替你执行，不会替你理解——你躲开的东西，最后都会在上线那天全部找回来。



恐惧还会穿上两件相反的衣服。

- 一件叫“不敢用”：怕被替代、怕跟不上，于是把 AI 关在门外。
- 另一件叫“不敢看”：知道自己看不懂，干脆不读 `diff`、不点开生成结果。前者让你停在原地，后者让你闭着眼开车——都出不了好结果。

但最深的一种恐惧，是**不敢承认自己不懂**。不懂装懂地点点头，把每一行来路不明的代码放进仓库，这才是最危险的时刻。

绿灯军团从没说过“意志强大的人就不再恐惧”，他们说的是“克服恐惧”。`Vibe Coding` 里真正的勇气也不是不用 AI，而是用完之后，还有胆量逐行看完它写的每一行。

------

## 写在最后

`Vibe Coding` 和绿灯戒指，本质上是同一个**放大器模型**：

1. **意志决定造什么** —— 需求越清晰，产出越完整；AI 放大的是你的意图，不是替你产生意图。
2. **知识划定想象力的边界** —— 先有图纸，后有造物；先懂代码，才审得出代码里的坑。
3. **三种姿态对应三种命运** —— 依赖者被带进坑里，拒绝者被时代抛下，共创者让 AI 飞得更快。

戒指不会让你成为灯侠，它只会让已经是灯侠的人飞得更快。下次打开 `Cursor` 之前，不妨想想：你的意志足够集中吗？你的图纸准备好了吗？你敢不敢看它写出来的每一行？

易普AI《很多 Vibe coder 都有一种幻想》:  [https://mp.weixin.qq.com/s/2eghzc9-SD_384TNudbKiA](https://mp.weixin.qq.com/s/2eghzc9-SD_384TNudbKiA)

> 最近我发现，很多人对 AI 编程有一个误解。
>
> 他们以为：“我不会代码没关系。”“我不懂产品没关系。”“我不会设计没关系。”“我只要会跟 AI 聊天，就能做出一个爆款项目。”
>
> 听起来很爽。
>
> 但问题是，AI 确实降低了门槛，但没有取消门槛。
>
> 你不会写代码，AI 可以帮你写。但你不知道自己要什么，AI 救不了你。
>
> 你不会改 bug，AI 可以帮你排查。但你连问题出在哪都看不懂，AI 也会把你带进坑里。
>
> 你不会做产品，AI 可以帮你生成页面。但用户为什么要用，你还是得自己想。
>
> 所以很多 Vibe Coder 的真实状态是：不是在“用 AI 创业”，而是在“用 AI 逃避学习”。
>
> 幻想 AI 能替自己完成所有事：替自己思考，替自己判断，替自己试错，替自己赚钱。
>
> 但现实是：AI 只会放大你的能力，不会凭空替你制造能力。
>
> 你有产品思维，AI 会让你快十倍。你有审美，AI 会让你出图更快。你有技术基础，AI 会让你迭代更猛。你有商业判断，AI 会帮你快速验证。
>
> 但如果你什么都没有，AI 放大的可能只是你的混乱。
>
> AI 不是捷径，它只是把真正有执行力的人，送得更快。
