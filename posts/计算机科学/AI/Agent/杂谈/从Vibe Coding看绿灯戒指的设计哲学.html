从Vibe Coding看绿灯戒指的设计哲学

提示

  • 哈尔·乔丹：“我心里想得出什么，就能创造出什么——只要我集中意志。”
  • 约翰·斯图尔特：“戒指成就不了灯侠，是灯侠成就了戒指。”
  • 凯尔·雷纳：“戒指只受想象力的限制。”

如果你看过《绿灯军团》，你一定记得那个画面：一枚小小的绿灯戒指套上手指，绿光一闪，心里想到什么，手上就出现什么。最近我也在看这部美剧，主角们说的话让我醍醐灌顶——绿灯戒指被称为宇宙中最强大的武器之一，但它的力量从来不来自戒指本身，而来自佩戴者的意志。

本DC粉强烈推荐大家都去看《绿灯军团》。

绿灯侠无法想象出自己不知道的东西

提示

哈尔·乔丹那句台词是整个绿灯设定的地基：“我心里想得出什么，就能创造出什么——只要我集中意志。”

注意后半句。“集中意志”不是蛮力，是清晰的意图。他能用戒指造出精密仪器，不是因为力气大，而是因为脑子里先有构造物的完整图像。

漫画里有一段：盖伊·加德纳被人拦腰斩断，所有人都以为他死了——他躺在地上，用戒指一寸一寸把自己重新拼了回来。那一刻戒指没有变得更强，变得更强的是他不想死的意志。

提示

凯尔·雷纳说“戒指只受想象力的限制”。

这话还有个被忽略的后半句：想象力本身有边界，边界就是知识。

约翰·斯图尔特是建筑师出身，他的造物永远有结构感。他不用蛮力，而是用工程思维去构建。美剧《绿灯军团》里有个细节值得玩味：他先研究了盾构机的图纸，才用灯戒把它造了出来。图纸在前，造物在后——灯戒能瞬间造出万物，唯独造不出他脑子里没有的东西。

漫画里的灯侠们也不是生来就会造一切，他们无法想像出自己不知道的事物。戒指连着军团世代积累的图纸和知识库，他们同样要学，学完才会造。

所以，这就是绿灯戒指和绿灯侠。只有意志力足够强大的绿灯侠，才能够驾驭绿灯戒指。而灯戒的能力边界，实际上是来自于绿灯侠的想象力。

AI的能力边界

提示

是的，不仅绿灯戒指存在能力边界，AI也同样存在能力边界。

很多新手 Vibe coder 都有一种幻觉，他们使用AI写了个项目出来后，突然就有自信了，觉得AI什么都能做，觉得自己无所不能了。完了之后，他们又开始骄傲了，觉得计算机专业也不过如此，到处开始散播计算机要完蛋了的言论，妄想着不学习，仅仅通过AI就可以超过计算机专业的人。你看各大评论区清一色的“全部交给AI就好了”，“AI时代再去学编程语言已经没有意义了”，“有了AI就不需要程序员了”，大概率就是这类人。

可是事实上呢，事实上AI被他们过度神化了，AI并不是万能的。

所以，那AI到底是什么？

先谈AI的本质

我最近在用多邻国学习外语的时候，突然就想清楚了这一个问题。世界上第一个翻译是如何出现的？人类的第一门语言是如何出现的？是文字先于语言，还是语言先于文字？

然后我继续联想，想到了一个关键的问题，人类之所以成为地球霸主，比其他动物都要聪明，可不就是因为语言吗？

动物也能积累经验。一只老猫知道如何捕捉更敏捷的猎物，但它的经验只能存留在自己脑子里，死后随之消失。后代必须重新摸索。这就是为什么动物的“知识”几万年几乎没有进步。

语言的出现，改变了这一切，这是一个循序渐进的过程：

  1. 语言的出现：个人学会的技能，可以通过语言告诉另一个人，不需要重新经历试错；知识可以跨代传递；
  2. 文字的出现：知识不再只活在人的脑子里，可以被固定到身体之外的东西上；不需要见面、不需要口口相传，就能跨越时间和空间传递；记忆会模糊、传言会走样，文字让知识原样保存下来，人类的知识从此开始积累成册；
  3. 计算机的出现：知识被装进机器，存储和检索不再靠人脑翻找；但计算机只会执行人类写好的规则——人把知识翻译成程序，机器按部就班地照做，一步不会多，一步也不会少；
  4. AI的出现：机器第一次不需要人类把规则一条一条写出来；它自己从海量数据里学统计规律，学会预测最合理的下一个词；知识开始不经过“人写规则”这一步，直接沉淀进机器里。

如果你用象限图将这一过程画出来，你会发现人类的知识是在这两百年内才开始指数级上升的。

AI，实则是语言的进化形态。AI甚至可以看作人类语言的“镜像”：没有人类语言的语料积累，就没有现在的AI；AI能做推理，本质上是因为语言本身就已经承载了逻辑结构。

警告

所以，AI不是神！！！绿灯戒指也同样不是神。

人往往对自己无法解释、无法掌控的事物赋予超出现实的意义，古代把雷电天象归为神迹，现在又把看不懂的技术神话为某种“无所不能”的力量。AI确实被很多不深入了解它的人过度神化了。

不过，与其说这是“无知”，不如说是一种面对复杂事物时本能的简化思维——我们总希望能用某种宏大叙事去理解未知。但AI的“能力边界”恰恰是理解它最好的切入点：

AI不会思考，它只是在海量数据中做概率计算；AI没有意识，它的所有回复都是模式匹配的产物；AI也会犯错，会编造内容，会被逻辑陷阱困住，会因为训练数据而带偏见。它的能力边界是明确的：能处理语言、图像、代码，但它不理解意义、没有自我、没有情绪、没有真正的创造力。

真正值得警惕的不是AI被神化，而是“要么神话、要么贬低”的二极管心态。AI既不是万能的神，也不是泛泛之辈。它就是一个工具，有擅长的事，也有做不了的事。

人们应当对技术保持敬畏但不过度迷信，保持好奇但不放弃审视。不卑不亢，理性看待AI，比神化或恐慌都更有价值。

大语言模型实际上是在海量数据中学习到的统计规律，来预测最合理的下一个词；但在这个过程中，它涌现出了某种近似推理的能力。而这种能力，和绿灯戒指一样，存在边界。

绿灯戒指的能力边界由两大因素组成：1.军团的知识库，2.灯侠的意志力和想象力。

而AI的能力边界，同样由两大因素决定，一个是给AI的训练数据，还有一个，就是使用者的知识储备。

然后说第一个原因，给AI的训练数据。

提示

训练数据之于大语言模型，就好比绿灯军团的知识库之于绿灯戒指。决定了能力的上限。

微软的Copilot 之所以强大，一方面原因就是因为从 GitHub 上学习了无数的开源代码。

你让AI写前端和后端，AI为什么写得又快又准，就是因为写的人多，网上的开源代码多，AI不容易出错。一旦到了特定的业务代码，非常小众的领域，AI就没招了，会频频出错。这不怪AI，刚才提到了，大语言模型实际上是通过学习来预测下一个词。训练数据少，AI出错就在所难免。

C# / TypeScript 的创造者Anders Hejlsberg说：

我很确定 AI 写不出我们的 TypeScript 编译器，它就是做不到。我们试过了，它做不出来。

而且我们的编译器也不是普通代码——训练集里几乎没见过这种东西。

编译器我见过一些，但没见过像这一个这样、用这些概念、按我们这种方式实现的。

AI 本质上是一台巨大的随机机器，记住了整个互联网，并对记下来的东西做一定外推；但没见过，就未必能写好。

当然，讲TypeScript 编译器的例子，是有些太夸张了，我们平常的编程当然是涉及不到这么高深的东西的。

但是这里是想给广大读者说明一个道理，凡事都得祛魅，AI不是什么外太空产物，不是什么很神秘，很神奇的魔法，它不是无所不能的。AI也是人造出来的，它不是神，它也有它的能力边界。

OK，我们来看看，当遇到小众领域，AI无法解决问题时，两类人的处理方法有何不同。一类人只会觉得AI也不过如此；而另外一类呢，他们自己研究，并解决问题，然后开源给大家。最后呢，AI重新学习新开源的知识，然后所有人都知道如何解决这个问题了；然而，背后那些人的努力和奋斗呢，被他们一句“全部交给AI就好了”，一句话掩盖。

最后再说最重要的原因，使用者的知识储备

提示

AI的训练数据，可以决定一个AI的上限；

而使用者的知识储备之于AI，就好比绿灯侠的意志力和想象力之于绿灯戒指。决定了能力的下限。

  • 如果你根本就不了解你想要什么，你只会问出很贫瘠的问题；面对完全陌生的领域，甚至，你连如何正确提问都不会知道；因为你不知道，AI也不会替你修复。
  • 如果你非常了解你正在做的事，那么你就可以问出非常具体的问题，并且严格规范AI的输出，得出的结果可以说绝对是天差地别。

所以说，你看，Vibe Coding和绿灯戒指如出一辙。放在一起比较，其实揭示了一个核心真相：它们不是魔法，而是放大器。使用者的知识越丰富，越能发挥出AI的能力。就好比约翰·斯图尔特说的：“戒指成就不了灯侠，是灯侠成就了戒指。”

你让 AI 做一个“帮用户记账的工具”，和让 AI 做“一个能让用户在三秒内完成记账、并且自动生成月度消费洞察、还能提醒预算超支的工具”，产出的东西天差地别。

AI 可以帮你生成 2000 行代码，但如果你不知道哪部分是核心逻辑、哪部分是边缘情况、哪里会出性能瓶颈，你得到的只是一堆“看起来能跑”的代码——就像没有建筑师的图纸，凭空用灯戒捏出来的房子，看着像样，风一吹就塌。

Vibe Coding 的坑，只有懂行的人才看得见。

比如 AI 很爱写 if (status == "XXX")：把一个来历不明的字符串直接焊死在判断条件里，业内叫魔法数。老手一眼就知道这是病——判断条件应当来自常量或枚举，而不是凭空蹦出来的字面量。可没系统学过计算机的人不会觉得这行有问题：能跑啊。长此以往，代码越来越混乱，出不出事故只是时间问题。

更别说AI喜欢层层嵌套的 try catch、AI 特有的过度优化、上下文一长就出现的“记忆错乱”……没亲手写过代码的人，连该在哪儿警觉都不知道。

所以：灯侠造不出他不知道的东西，Vibe Coder 也审不了他看不懂的代码。AI 只能在你的视线之内工作——你看不见的坑，它不会替你填上。 AI的屎山代码不会自己消失，只会一年比一年难维护。

一个没有训练过的灯侠拿到戒指，第一反应是造一团光球。 他不知道光球能干什么，不知道能量怎么塑形，不知道什么时候该进攻什么时候该防御。他不是被敌人打败的，他是被自己的无知打败的。

那些“用 AI 逃避学习”的人，本质上是在做一件事：试图跳过灯侠的训练，直接靠戒指本身的力量取胜。但绿灯军团里从来没有这种灯侠——每一个能独当一面的灯侠，都是先有了意志、判断力和想象力，戒指才成了他们手中的武器。

Vibe Coding 的幻想

以下原文来自----易普AI《很多 Vibe coder 都有一种幻想》: https://mp.weixin.qq.com/s/2eghzc9-SD_384TNudbKiA

最近我发现，很多人对 AI 编程有一个误解。

他们以为：“我不会代码没关系。”“我不懂产品没关系。”“我不会设计没关系。”“我只要会跟 AI 聊天，就能做出一个爆款项目。”

听起来很爽。

但问题是，AI 确实降低了门槛，但没有取消门槛。

你不会写代码，AI 可以帮你写。但你不知道自己要什么，AI 救不了你。

你不会改 bug，AI 可以帮你排查。但你连问题出在哪都看不懂，AI 也会把你带进坑里。

你不会做产品，AI 可以帮你生成页面。但用户为什么要用，你还是得自己想。

所以很多 Vibe Coder 的真实状态是：不是在“用 AI 创业”，而是在“用 AI 逃避学习”。

幻想 AI 能替自己完成所有事：替自己思考，替自己判断，替自己试错，替自己赚钱。

但现实是：AI 只会放大你的能力，不会凭空替你制造能力。

你有产品思维，AI 会让你快十倍。你有审美，AI 会让你出图更快。你有技术基础，AI 会让你迭代更猛。你有商业判断，AI 会帮你快速验证。

但如果你什么都没有，AI 放大的可能只是你的混乱。

AI 不是捷径，它只是把真正有执行力的人，送得更快。

社区对Vibe Coding 的看法

Andrej Karpathy 说

2025 年 2 月，Vibe Coding 这个词的发明者 Andrej Karpathy 说，这是一种“完全交出代码控制权”的玩法——不读 diff，报错就原样丢回模型，直到程序“差不多能用”。他同时把适用范围说得很窄——一次性的周末项目。

这和“AI 辅助开发”并不是一回事。Simon Willison 给过一个实用边界：代码即使由模型生成，只要你审查、测试并能解释它，依然是在做软件开发。

  • 普通开发模式:先建立心智模型，再写或生成代码。
  • Vibe 模式:先追求可见结果，把理解推迟到以后，甚至永久跳过。
  • AI 工程化模式:让模型扩大产出，让人保留解释、验证与决策权。

判断：Vibe Coding 不是“不会写代码的人用 AI”，而是“暂时不关心代码本身”的模式。高手也会 Vibe，只是更清楚什么时候该停。

来源：Karpathy 原始帖文，2025；Simon Willison

Stack Overflow 用户统计

生成速度越快，未被理解的代码也可能积累得越快。2025 Stack Overflow 开发者调查给出了四个值得并排看的信号：

72%表示 Vibe Coding 不是其专业流程的一部分

46%不信任 AI 输出准确性；信任者为 33%

66%最常遇到“几乎正确，但不完全正确”

45%认为调试 AI 生成代码更耗时

这些数字不能证明 AI 代码必然更差，却提示了一个结构性问题：生成成本下降后，验证会成为新的瓶颈。

每增加 25% AI 采用率的相关变化

  • 交付吞吐量　−1.5%
  • 交付稳定性　−7.2%

这是统计相关，不是因果证明。DORA 推测更快生成可能扩大变更批次，使评审和发布更困难。

如果生成速度翻倍，测试、评审和发布机制没有同步升级，风险只会在更靠近用户的地方结算。

禁止AI提交代码的组织

  • Zig：最严格之一。PR、issue、评论、翻译、头脑风暴、找 bug 都不允许用 LLM；维护者要的是“人”，不是“AI 产出的补丁”。

  • OpenJDK：Oracle 旗下，2026 年临时政策——代码、文本、图片、PR、邮件、wiki、bug report 都不得包含 LLM / 扩散模型生成内容；改了 10 行也不行，因为“血统”还是 AI。

  • Godot: 拒绝 AI 生成代码提交

  • Gentoo Linux：2024 年就禁止用 NLP/LLM 工具生成 ebuild、代码、文档、消息、bug report。

  • QEMU：拒绝任何被认为包含/源自 AI 生成内容的贡献（后来对极小机械修改有松动）。

  • SDL：明确拒绝 LLM 生成代码。

  • Servo：禁止所有 LLM 生成贡献。

  • Vim Classic：不接受任何 AI 生成代码。

  • Redox OS：禁止 LLM 生成代码，并用 DCO 强化“人负责”。

  • NetBSD：不叫“禁止”，但把 LLM 代码归为 tainted，无核心团队书面批准不能进。

  • RPCS3：禁止自主 AI agent 提交，隐瞒 AI 参与可封号。

  • Ghostty：不是全禁，但 drive-by AI PR 直接关；AI 辅助要披露、要预批准议题、要人能解释。

  • LLVM：禁止自主 AI 提交；AI 辅助必须人类审查且能独立解释。

  • Linux 内核：不算禁，但 Signed-off-by 必须是人，AI 参与用 Assisted-by；本质是把“责任”焊在人身上。

恐惧：灯戒唯一的弱点

绿灯戒指的力量来自意志，它唯一的弱点，是恐惧。

漫画里，灯侠一旦被恐惧攥住，光构就会颤抖、变暗，最后散成一地碎光。所以军团选人只有一个标准：不是看谁最有力量，而是看谁能克服巨大的恐惧。 戒指从不奖励毫无畏惧的人，它奖励的是怕得要命、仍然举起手的人。

Vibe Coding 里的恐惧长这样：

  • 你讲不清自己的业务逻辑，于是指望 AI 替你讲清；
  • 出了BUG，你感到恐惧，于是你指望 AI 替你找出。

可 AI 只会替你执行，不会替你理解——你躲开的东西，最后都会在上线那天全部找回来。

但最深的一种恐惧，是不敢承认自己不懂。不懂装懂地点点头，把每一行来路不明的代码放进仓库，这才是最危险的时刻。

绿灯军团从没说过“意志强大的人就不再恐惧”，他们说的是“克服恐惧”。Vibe Coding 里真正的勇气也不是不用 AI，而是用完之后，还有胆量逐行看完它写的每一行。

写在最后

Vibe Coding 和绿灯戒指，本质上是同一个元模型：

  1. 意志决定造什么 —— 需求越清晰，产出越完整；AI 放大的是你的意图，不是替你产生意图。
  2. 知识划定想象力的边界 —— 先有图纸，后有造物；先懂代码，才审得出代码里的坑。
